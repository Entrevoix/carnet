## The stale-prebuild trap (read this before the next release)

`scripts/build-release-apk.sh` only **checks that** `android/` exists — it never
regenerates it. After #136 merged, `android/app/build.gradle` still read
`versionCode 1 / versionName "0.2.0"` from an older prebuild. Building without
regenerating would have produced an APK named `carnet-v0.4.0.apk` that
self-reported `0.2.0` — reintroducing the exact drift #136 existed to remove,
silently and with every test green.

**After any version change: `npx expo prebuild --platform android --clean` in
`apps/mobile`, then confirm `grep -nE "versionCode|versionName"
apps/mobile/android/app/build.gradle` before building.** CI is immune — the
`android-toolchain` composite action does a clean prebuild every run. This bites
local builds only, which is precisely where releases get hand-checked.

## Rig notes (cost real time this session)

- **comet's USB is unreliable.** It dropped mid-operation and did not return
  across an `adb reconnect`, a server restart, or a replug; later rango dropped
  too. Assume any long device sequence on comet can be cut off, and take the
  readback you need early.
- **rango has no LLM provider configured** — Base URL, API key, and Model are all
  empty, which is why its Recents is empty. It cannot stand in for Enhance
  testing without entering credentials, and the key cannot be copied off comet
  (secure store, never displayed again).
- **`screencap` on a Fold emits a multi-display warning strip before the PNG**,
  corrupting the file. Strip to the `\x89PNG` magic, or pass `-d <display-id>`
  (`dumpsys SurfaceFlinger --display-id` lists them). Taps need `input -d 0`.
