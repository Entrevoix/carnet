## The stale-prebuild trap (read this before the next release)

`apps/mobile/scripts/build-release-apk.sh` only **checks that** `android/` exists — it never
regenerates it. After #136 merged, `android/app/build.gradle` still read
`versionCode 1 / versionName "0.2.0"` from an older prebuild. Building without
regenerating would have produced an APK named `carnet-v0.4.0.apk` that
self-reported `0.2.0` — reintroducing the exact drift #136 existed to remove,
silently and with every test green.

**After any version change, all of these from `apps/mobile`:**
1. `export ANDROID_HOME="$HOME/Android/Sdk"` — `prebuild --clean` wipes
   `local.properties`, so a local Gradle run without this fails with "SDK
   location not found" (learned in the 2026-08-06 handoff; do not learn it a
   third time).
2. `npx expo prebuild --platform android --clean`
3. `grep -nE "versionCode|versionName" android/app/build.gradle` — confirm it
   reflects the bump.
4. Re-run `scripts/verify-notification-and-widget-prebuild.sh`,
   `verify-audio-decoder-prebuild.sh` and `verify-shortcuts-prebuild.sh` — a
   `--clean` regeneration is exactly when the config plugins can silently stop
   emitting what they should.
5. After building, verify the APK's cert before trusting it as a release:
   `apksigner verify --print-certs <apk>` must print
   `e5f5ed37e098e0da7b09a59734845b21c986a18d1994bbdb670d01e3c7a3eaf7`.
   `build-release-apk.sh` **falls back to the debug keystore and still exits 0**
   if the keystore config is missing — `release.yml` treats this exact
   fall-through as mandatory to check, and a debug-signed APK cannot upgrade a
   release-signed install without an uninstall that wipes all app data.

CI is immune — the
`android-toolchain` composite action does a clean prebuild every run. This bites
local builds only, which is precisely where releases get hand-checked.
